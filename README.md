# Jalaqy — фронтенд

Jalaqy («жалақы» — зарплата по-казахски) — облачный сервис расчёта зарплаты, налогов и кадров для малого бизнеса в Казахстане.

В репозитории — весь фронтенд:

- **лендинг** с листом ожидания;
- **веб-панель бухгалтера**;
- **мобильные экраны (PWA)** владельца и сотрудника.

Режим выбирается автоматически:

- **Пилот (Firestore)** — если в `.env.local` есть ключи Firebase. Настоящие компании, вход по паролю, реальная дата. См. [Пилот на Firebase](#пилот-на-firebase).
- **Демо** — без ключей. Данные из **мок-API в памяти**, вход с любым паролем и выбором роли, дата заморожена на 30 октября 2026.
- **HTTP-бэкенд** — если задан `JALAQY_API_URL` (см. [Подключение бэкенда](#подключение-бэкенда)).

Стек: Next.js 16 (App Router, Cache Components), React 19, TypeScript (strict), Tailwind CSS 4, Vitest, Playwright. Сторонней аналитики, CDN и внешних шрифтов нет: шрифты Onest и Golos Text раздаются с нашего сервера.

## Быстрый старт

Нужен Node.js 20+.

```bash
npm ci
npx playwright install chromium   # нужен только для e2e-тестов и скриншотов
npm run dev                       # http://localhost:3000
```

### Пилот на Firebase

Нужны в `.env.local`: `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY` (сервисный аккаунт) и `SESSION_SECRET` — длинная случайная строка, в production обязательна (`openssl rand -base64 48`). На хостинге (Vercel и т. п.) те же переменные задаются в настройках проекта.

**Как начать работать с реальной компанией**

1. Запустить приложение: `npm run dev:app` → <http://localhost:3002> (или открыть задеплоенное приложение).
2. На странице входа — «Новая компания? Зарегистрироваться» (`/register`): название, ваше имя, логин (почта или телефон `+7 7XX XXX XX XX`) и пароль от 8 символов. Тот, кто регистрирует, становится **владельцем**.
3. **Онбординг**: БИН, налоговый режим, месяц, с которого считать зарплату, сотрудники (вручную или CSV).
4. Дальше — панель `/app`: сотрудники, табель, расчёт, налоги. Бухгалтера, второго владельца и **сотрудников** (их кабинет — `/me`) добавляют в «Настройки» → «Пользователи и роли». Там же — сменить чужой пароль и закрыть доступ.

Роли:

- **Владелец** — всё: ведёт расчёт сам, подтверждает выплату, отмечает её выплаченной. На телефоне у него короткая сводка `/owner`, из неё — в панель и в профиль.
- **Бухгалтер** — всё в панели, кроме подтверждения: он отправляет расчёт владельцу.
- **Сотрудник** — только свои листки, отпуск и справки.

Месяц проходит статусы: расчёт готов → (бухгалтер отправил) → владелец подтвердил → зарплата выплачена → налоги оплачены (месяц закрыт). До выплаты расчёт можно вернуть на доработку.

Свой профиль (имя, смена пароля, выход): в панели — имя внизу меню, у владельца — аватар вверху сводки, у сотрудника — вкладка «Профиль». Если доступ закрыли или роль поменяли, человека при следующем действии выбросит на вход.

Закрытый пилот: задайте `JALAQY_SIGNUP_CODE` — без этого кода компанию не зарегистрировать. Без переменной регистрация открыта (не больше 5 компаний в час с одного адреса).

Консоль (нужна редко):

```bash
npm run admin -- list             # компании и пользователи
npm run admin -- backup           # копия базы в .backup/<время>.json (в git не попадает)
npm run admin -- password --login buh@romashka.kz --password "новый-пароль"   # если забыли пароль
npm run admin -- company --company "ТОО Ромашка" --name "Айгуль" --login buh@romashka.kz --password "…"
npm run admin -- wipe --yes       # стереть ВСЁ, необратимо — сначала backup
```

Пароли хранятся только хэшем (scrypt). После 5 неверных попыток вход для логина закрыт на 15 минут.

История расчётов компании начинается с месяца, выбранного в онбординге (меняется в настройках).

Что пока считается упрощённо: отпуск и больничный оплачиваются как рабочие дни (без среднего заработка), компенсации при увольнении нет, платёжки и справки — текстовые черновики.

### Два сайта: лендинг и приложение

Код один, а на Vercel из него сделаны два проекта. Каждый проект показывает свою часть по переменной `JALAQY_SITE`:

| Проект     | `JALAQY_SITE` | Что открывается                                                 | Ещё переменные                                       |
| ---------- | ------------- | --------------------------------------------------------------- | ---------------------------------------------------- |
| Лендинг    | `landing`     | `/`, `/privacy`, `/offer`, лист ожидания                        | `JALAQY_APP_URL` — адрес приложения                  |
| Приложение | `app`         | `/login`, онбординг, `/app`, `/owner`, `/me`; `/` ведёт на вход | `FIREBASE_*`, `SESSION_SECRET`, `JALAQY_LANDING_URL` |

Локально их можно запустить рядом:

```bash
npm run dev:app       # приложение — http://localhost:3002 (главная ведёт на вход)
npm run dev:landing   # лендинг   — http://localhost:3003 («Войти» ведёт в приложение)
```

На лендинге адреса приложения (`/login`, `/app/…`) перенаправляются на `JALAQY_APP_URL` с тем же путём. Приложение отдаёт `X-Robots-Tag: noindex`. Если `JALAQY_SITE` не задана, открывается всё сразу (локальная разработка, e2e). Правила — в [`src/lib/site.ts`](src/lib/site.ts).

### Демо-вход

Без ключей Firebase откройте <http://localhost:3000/login>:

1. Введите любой телефон (`+7 7XX XXX XX XX`) или email.
2. Введите любой пароль. Пароль `wrong` показывает экран ошибки.
3. Выберите роль в поле «Войти как (демо)»:

| Роль      | Куда попадает  | Что смотреть                                                           |
| --------- | -------------- | ---------------------------------------------------------------------- |
| Бухгалтер | `/app/payroll` | расчёт за октябрь, сотрудники, табель, налоги, настройки               |
| Владелец  | `/owner`       | итог к выплате, заявка на отпуск, «Подтвердить выплату»                |
| Сотрудник | `/me`          | расчётный листок (октябрь появится, когда владелец подтвердит выплату) |

Другие адреса:

| Адрес                | Что там                                             |
| -------------------- | --------------------------------------------------- |
| `/`                  | лендинг                                             |
| `/onboarding`        | настройка новой компании, импорт сотрудников из CSV |
| `/styleguide`        | токены, логотип и UI-кит во всех состояниях         |
| `/privacy`, `/offer` | заглушки юридических документов                     |
| `/offline`           | офлайн-экран PWA                                    |

Демо-данные живут в памяти процесса. Вернуть исходную компанию: «Настройки» → «Сбросить демо-данные» или перезапуск сервера.

## Расчёт зарплаты и ставки

Ядро — [`src/lib/payroll/`](src/lib/payroll). Это чистый TypeScript без UI и I/O.

- **Ставки и пределы** лежат в [`rates/2026.ts`](src/lib/payroll/rates/2026.ts): МЗП, МРП, проценты, множители пределов, порог 15% ИПН, вычет. В формулах цифр нет.
- **Новый год:** создать `rates/2027.ts` и добавить строку в [`rates/index.ts`](src/lib/payroll/rates/index.ts).
- **Производственный календарь** (праздники и переносы) — [`calendar/2026.ts`](src/lib/payroll/calendar/2026.ts). Нужен для неполного месяца.
- **Округление** — одна функция `roundTenge` в [`round.ts`](src/lib/payroll/round.ts).
- **ИПН** считается нарастающим итогом с начала года ([`ipn.ts`](src/lib/payroll/ipn.ts)): 10% до 8 500 МРП, 15% сверх.
- **Тесты** сверяют цифры из дизайна до тенге: 320 000 → на руки 266 415; 6 сотрудников → в бюджет 615 546, ФОТ 2 174 436.

> ⚠️ Формулы нужно сверить с практикующим бухгалтером. Спорные места перечислены в отчёте Фазы 3: база порога 15%, вычет при низком окладе, ОПВ ниже МЗП, особые категории сотрудников.

Тот же модуль считает калькулятор на лендинге и все суммы в моке. Захардкоженных сумм в интерфейсе нет.

## Подключение бэкенда

Страницы и Server Actions получают данные только через `api` из [`src/lib/api/index.ts`](src/lib/api/index.ts):

```ts
export const api: JalaqyApi = process.env.JALAQY_API_URL
  ? createHttpApi(process.env.JALAQY_API_URL)
  : mockApi;
```

| Файл                                       | Что в нём                                                                            |
| ------------------------------------------ | ------------------------------------------------------------------------------------ |
| [`contracts.ts`](src/lib/api/contracts.ts) | типы данных (DTO): `Employee`, `PayrollRun`, `Payslip`, `TaxPayment`… — JSON бэкенда |
| [`endpoints.ts`](src/lib/api/endpoints.ts) | **контракт эндпоинтов**: `"МЕТОД /путь"` → тип тела и ответа                         |
| [`client.ts`](src/lib/api/client.ts)       | интерфейс `JalaqyApi`, ошибка `ApiError`                                             |
| [`http.ts`](src/lib/api/http.ts)           | готовый HTTP-клиент, типизированный по `endpoints.ts`                                |
| [`mock/`](src/lib/api/mock)                | реализация в памяти: поведение, которое должен повторить бэкенд                      |

Фрагмент контракта:

```ts
export interface Endpoints {
  "POST /auth/login": E<LoginInput, Session>;
  "GET /payroll/{period}": E<void, PayrollRun>;
  "POST /payroll/{period}/submit": E<void, PayrollRun>;
  "POST /payroll/{period}/approve": E<void, PayrollRun>;
  "GET /employees/{id}/payslips/{period}": E<void, Payslip>; // {period} = ГГГГ-ММ | latest
  // … всего 31 эндпоинт, см. src/lib/api/endpoints.ts
}
```

Соглашения:

- **Формат данных:**
  - суммы — целые тенге;
  - даты — ISO (`2026-10-31`), время — UTC;
  - период — `ГГГГ-ММ`.
- **Ошибки:** HTTP 4xx/5xx с телом `ApiErrorBody`:

  ```ts
  { code: "validation" | "not_found" | "conflict" | "forbidden" | "unauthorized" | "server",
    message: string,
    fields?: Record<string, string> } // текст ошибки по каждому полю формы
  ```

  Формы подсвечивают поля из `fields`, остальное показывают общим сообщением.

- **Статусы расчёта** (`PayrollStatus`): `draft → calculated → awaiting_approval → approved → paid → closed`. Владелец может подтвердить из `calculated` или из `awaiting_approval`.
- **Листок сотрудника** виден только после подтверждения (`approved`, `paid`, `closed`). Это правило мока, бэкенд должен его повторить.
- **Права:**
  - бухгалтер — всё в своей компании;
  - владелец — смотрит панель и подтверждает выплату;
  - сотрудник — только свои `/employees/{его id}/…` и `POST /absences/requests`.

  `proxy.ts` проверяет роль только предварительно, окончательная проверка — на бэкенде.

Что заменить при подключении:

1. **Сессия.** Сейчас [`src/lib/session-codec.ts`](src/lib/session-codec.ts) хранит роль в неподписанной cookie (JSON в base64url). Нужно:
   - выдавать подписанный токен в httpOnly-cookie на `POST /auth/login`;
   - проверять подпись в `decodeSession`;
   - передавать токен в `createHttpApi(url, getToken)`.
2. **Лист ожидания.** Интерфейс `WaitlistRepository` в [`src/lib/waitlist/repository.ts`](src/lib/waitlist/repository.ts): заменить JSON-файл на PostgreSQL или вызов бэкенда. Роут `/api/waitlist` не меняется.
3. **«Сегодня».** С бэкендом используется реальная дата, `JALAQY_TODAY` не задавать.
4. **Демо.** Демо-выбор роли при входе (`demoRole`) и кнопка «Сбросить демо-данные» видны только в демо-режиме (`isDemo`: нет ни `JALAQY_API_URL`, ни ключей Firebase).

## Данные и приватность

- **Сервер.** Все данные, включая заявки листа ожидания, остаются на нашем сервере. Сторонних форм, мессенджеров и аналитики нет. e2e-тест проверяет, что страницы не делают внешних запросов.
- **Шрифты.** `next/font` скачивает их при сборке и раздаёт с нашего домена.
- **Service worker** кэширует только офлайн-экран, иконки и статику. Страницы с суммами и персональными данными в телефоне не сохраняются.
- **Заявка листа ожидания** хранится вместе с текстом и версией согласия, UTM-метками и источником. Чтобы отсеять ботов, есть скрытое поле-ловушка и лимит 5 заявок за 10 минут с одного IP. IP берётся из `X-Real-IP` или `X-Forwarded-For` — **за nginx, который перезаписывает эти заголовки**.

## Тесты

- **Юнит (Vitest):** расчёт зарплаты, форматирование, валидация, импорт CSV, мок-API, сессия, лист ожидания, компоненты UI-кита (Testing Library). Отдельный тест проверяет, что строки интерфейса не захардкожены вне `src/i18n`.
- **e2e (Playwright),** проекты на ширинах 390 и 1440:
  - вход и выход;
  - сценарии бухгалтера, владельца и сотрудника;
  - PWA и офлайн;
  - лендинг и `/api/waitlist`;
  - экраны ошибок и повтор;
  - клавиатурная навигация.
- **Доступность:** [`tests/e2e/a11y.spec.ts`](tests/e2e/a11y.spec.ts) — axe-core (WCAG 2.1 AA) на всех экранах при 390, 768, 1280 и 1440, плюс проверка горизонтальной прокрутки и единственного `h1`.

## Локализация

Все строки лежат в [`src/i18n/ru/`](src/i18n/ru) по разделам. [`kk.ts`](src/i18n/kk.ts) — частичный словарь того же типа: недостающие ключи берутся из `ru`. Шрифты подключены с `cyrillic-ext`, казахские буквы отображаются.
